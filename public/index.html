04

猛蹬：怎么蹬

6 个项目 · 3 类工作流 · 展开收起

有任务再猛蹬，不为清空额度空转。6 个明确支持 Codex 的外部项目：2 个帮你拆任务，2 个帮你并行，2 个帮你持续执行。按任务选一种，不必全部安装。

文档与源码核验 · 2026-10-22

怎么选
  • 一个需求做扎实：Superpowers / Spec Kit。
  • 多个独立任务并行：Claude Squad / Superset。
  • 已有明确计划持续执行：Ralph Orchestrator / ralphex，先检查权限、隔离与停止条件。
规划与质量

Superpowers ↗

把需求讨论、实施计划、任务执行、TDD 和代码复核串起来，适合把一个功能做完整，而不是反复催“继续”。

怎么开始：按上游 Codex 安装说明启用，先确认需求、设计和验收条件。

注意：这是工作方法和技能，不会增加额度；小任务和明确验收比空转更有用。

MIT · 上游说明 / 核验依据 ↗

规划与质量

Spec Kit ↗

用规格、计划和任务清单组织开发，支持 Codex 集成。适合模糊需求、多模块功能和需要留存的决策。

怎么开始：按 Codex 集成文档初始化，依次完成需求、计划、任务和实施，每阶段审查后继续。

注意：不是无人值守循环；别把文档数量当成果，最终仍需测试和行为验收。

MIT · 上游说明 / 核验依据 ↗

并行任务

Claude Squad ↗

虽然名字带 Claude，也支持 Codex。通过 tmux 会话、独立 Git worktree 和分支管理多个任务，集中查看状态和差异。

怎么开始：准备 Codex、tmux 和 gh，按上游用法开始两个互不依赖的小任务。

注意：worktree 不是安全沙箱，也不会消除合并冲突。先复核差异，再合并。

AGPL-3.0 · 上游说明 / 核验依据 ↗

并行任务

Superset ↗

把 Codex 会话、独立 worktree、差异查看和浏览器预览放在一个桌面工作台，适合并行推进功能、测试和文档。

怎么开始：加入已有仓库，每个任务建一个工作区，选择 Codex，再检查 Changes 并运行测试。

注意：macOS 是主要平台，Linux 为实验性，Windows 暂无。worktree 不是沙箱；许可为 ELv2，不是 MIT。

Elastic License 2.0 · 上游说明 / 核验依据 ↗

持续执行 · 进阶

Ralph Orchestrator ↗

用事件和不同角色组织循环，支持 Codex 后端、任务记录和验证门槛，适合能自动验收的长任务。

怎么开始：先写目标和验证命令，配置迭代数、时长与停止条件，检查启动参数再运行。

注意：核验的 Codex 后端默认带 --yolo。不要在日常机器上盲目运行；先审查权限并提供外部隔离，提示词不等于沙箱。

MIT · 上游说明 / 核验依据 ↗

持续执行 · 进阶

ralphex ↗

读取带任务勾选项和验证命令的计划，逐项执行、提交，再进行多轮复核；支持 Codex 原生执行和 worktree。

怎么开始：先准备小计划，在隔离环境核对 CLI 版本、权限和迭代上限，再试一轮完整执行。

注意：要求 Codex CLI ≥ 0.130.0；Codex 模式默认 danger-full-access，并自动提交。同模型自审不是独立验证，不能默认允许推送或部署。

MIT · 上游说明 / 核验依据 ↗
