# 预告与到账观察的闭环展示

2026-10-31 用户需求：每轮“要重置了”的消息，后续补充实际到账事件；本人通过钉钉收提醒，并补查历史。后续已按横向可缩放甘特时间轴实现，运行合同见 [cycle-timeline.md](cycle-timeline.md)；下文保留初始设计。

## 沿用现有每轮卡片

继续使用 `public/app.js` 的事件分组和 `event-track`，不增加第二套历史页面。卡片折叠时保留轮次日期、重置类型及三个状态；展开后看各节点证据。

```text
本轮全量重置                         已观察到账号额度恢复

● 已预告 ───── ● 官方称已完成 ───── ● 账号恢复观察
  原帖时间       原帖时间              两次采样之间

公开预告：原帖链接
官方确认：原帖链接；没有确认则保持“待确认”
执行观察：某个受监测账号的weekly额度已恢复
到账时间：采样前时间—采样后时间，不能伪造精确执行时刻
关联依据：同一轮引用关系 / 单一活动轮次的时间匹配
原因：全局自动发放、手动用卡等尚未确定时明确保留未知
通知：本人钉钉已投递 / 处理中 / 结果未知
```

三段不是严格强制先后：账号可能先于官方确认恢复；只亮已有证据的节点，不因一手完成公告自动点亮到账。源帖缺失或时间匹配有歧义时，观察留在“未归属”，不强行补闭环。

## 等待与异常

- 只有预告：显示“等待执行证据”，列最后成功复查时间及下次复查。
- 官方称完成但没观测到个人变化：显示“官方已确认 · 账号到账待验证”。1/3小时复查各留记录，不说保证到账。
- 确认额度恢复：新增独立观察节点，保留原预告和所有“尚未确认”记录；不能改写历史。
- Mac离线、登录过期、来源失败：显示“复查不可用 / 覆盖未知”，不显示“未到账”。
- 正常周窗口到期：单独记“周补充”，不据此认定公开预告已经执行。
- 重置卡：用“已发卡 → 可用 → 已使用 / 已过期”，不能套成自动全量重置。卡的获得与使用是两个事件。

## 数据与公开边界

本机 `.wrangler/personal-usage-watch/state.json` 持久保存公开轮次、个人采样、到账观察与通知回执；采样变更已有实现。每轮采用稳定ID，关联源post IDs；先落观察，再通知。仅有时间匹配时关联标为推断。

公共前端只接脱敏后的观察事件：源轮次ID、观察类型、采样区间、证据等级和复查状态。不得把个人用量比例、账号ID、付费余额、登录信息、本人私聊ID、原始日志或截图放进公共API/静态包。公共文案用“已观察到账号恢复”，不能写成“你已到账”或“所有账号已到账”。本人具体数据只在私有记录/本人通知。

已实现经认证的脱敏观察写入、持久账本、公共API与横向周期图。现有Worker的 `personal_delivery_verified=false` 继续保留；那是公共服务是否能证明任意访问者本人到账的边界。

## 历史补录

Usage当前界面只展示过去30天的重置卡历史；读到的“获得/使用”可作为精确历史节点，不能当成全部全局重置历史。

本机token_count额度遥测已提取到私有文件，只解析quota字段，不复制聊天正文。历史缺少账号稳定身份，存在缓存滞后、并行会话和重置时间秒级抖动；窗口变化聚类、next reset减7天只算推断，不能批量写成确认到账。公开旧12轮与近期6条确认记录可用作关联来源，覆盖缺口必须保留。

历史导入静默，不补发过期通知。原始证据、推断、无法归属分别保存；新增的观察不抬高既有预告命中率。
