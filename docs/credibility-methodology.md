# 信源可信度与事件时间轴方法

这套方法只回答两个问题：**有没有值得提前知道的 reset 线索**，以及**历史上同类线索最后怎样收场**。它不预测私人 5 小时 / 周窗口，也不把社区热度当成全局事实。

## 1. 先把帖子合并成事件

分析单位是一轮已确认的 reset，不是一条 X 帖子。同一个上游消息被十个账号转发，仍然只有一个证据源。

每轮事件按以下顺序记录：

1. 最早线索：当前审计里谁最先说、原帖时间和链接。
2. 社区放大：侦察员、自动转发或独立传闻何时出现，是否只是复述同一条上游。
3. 官方确认：一手来源何时确认已经执行或即将执行。
4. 执行观察：个人账户是否到账、是否出现异常；它是弱观察，不代表所有账户。
5. 最后结果：hard reset 的官方确认，或 banked reset 的可用观察。

时间戳按 `Asia/Shanghai` 展示，同时保留原始 UTC。没有 post ID 或精确时间的环节只写为证据缺口，不补造“看起来很精确”的节点。这一点沿用 Seed 的确定性时间轴规则：已知时间先排序，未知保持未知。

## 2. 信源等级和单条内容等级分开

这里简化采用 [MISP Admiralty Scale](https://github.com/MISP/misp-taxonomies/tree/main/admiralty-scale) 的核心思想：来源可靠性与具体信息可信度是两个维度。

| 信源角色 | 它能说明什么 | 默认使用方式 |
| --- | --- | --- |
| 一手确认源 | 是否真的宣布或执行 | 可形成高置信确认；弱暗示仍按弱内容处理 |
| 社区侦察员 | 更快找到隐藏回复或把暗语说清楚 | 用于提高发现速度，必须回链一手原帖 |
| 自动转发 / 分发 | 更快把已有线索送达 | 同源转述，不增加独立证据数量 |
| 社区传闻 | 提供一手缺失时的候选线索 | 默认低置信；需要后续验证 |
| 个人到账 / 异常 | 某个账户的执行状态 | 默认弱观察；不能单独升级为全局 reset |

单条内容强度分为：官方确认、明确未来预告、语境型提示、同源转述、社区风声、个人弱观察、stale。即使账号历史表现不错，一条含糊或迟到的帖子仍然按弱内容显示。

## 3. 怎样升级一条弱观察

个人到账或异常反馈默认只进入“个人反馈”泳道。满足以下任一条件，事件才可升级：

- 一手来源明确确认全局 reset；
- 多个彼此独立的账户在相近窗口报告同一现象，且排除同一转发链后，形成社区交叉信号；
- 后续官方确认与社区观察匹配。

官方确认出现后，同一事件下更弱的转发与个人反馈仍保留在时间轴，但不重复发高等级提醒。这借鉴 [Prometheus Alertmanager](https://github.com/prometheus/alertmanager) 的分组、去重与 inhibition：强证据抑制同事件的重复弱告警，而不是删除审计记录。

## 4. 网页上的数字怎么读

- `收录信号`：当前审计或明确标注的实时账本中，去重保留了多少条相关帖子。
- `有用提前`：在可评估的已确认事件中，有多少次该来源在结果前提供了可用线索。
- `清楚预警`：内容足够明确，可以让用户提前安排本来就要做的任务。
- `通常提前`：有精确时间样本的中位提前量；它描述历史，不预测下一次时间。
- `漏掉 / 迟到 / 矛盾`：没有覆盖、事件后仍发 incoming，或前后判断冲突的事件数。

这些都是**事件条件下的覆盖统计**。最近 10 次样本全都是“最后确实发生了 reset”的事件，没有完整收录未发生 reset 的所有日期和误报，因此不能计算预测准确率、precision 或校准概率。

## 5. 成熟项目带来的约束

- [Timesketch](https://github.com/google/timesketch)：把不同来源归一成可排序事件，并保留标签、评论与原始证据。
- [OpenCTI](https://github.com/OpenCTI-Platform/opencti/blob/master/docs/docs/reference/data-processing.md)：去重与合并时保留关系完整性，置信度是数据本身的一部分。
- [MISP taxonomies](https://github.com/MISP/misp-taxonomies)：分开评估来源可靠性与信息可信度。
- [Prometheus Alertmanager](https://github.com/prometheus/alertmanager)：同一事件分组、去重，强证据抑制重复弱告警。
- [Bellingcat Auto Archiver](https://github.com/bellingcat/auto-archiver)：原始链接、归档状态和处理结果应可追溯。当前项目先保留 X post ID、时间和官方 URL；后续如做内容归档，必须另行核对 X 条款与开源分发边界。

## 6. 当前证据缺口

- 部分较早社区转发只保留了审计结论，没有 post ID 或秒级时间，因此不会出现在精确时间轴节点里。
- 社区账号的非事件日误报分母尚未完整回填。
- 个人到账只能说明单个账户，不能证明所有套餐、地区和账号已同步完成。

机器可读数据见 [`../data/reset-events.json`](../data/reset-events.json) 与 [`../data/source-scorecard.json`](../data/source-scorecard.json)。`npm run backtest` 会复算摘要、中位提前量、时间轴顺序和结局节点。
